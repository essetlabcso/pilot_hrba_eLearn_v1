# 04 Agora-to-HRBA Adaptation Rules

## Preserve from Agora
Preserve these design and interaction patterns:

- two-layer platform/player architecture;
- course catalogue and course overview before player launch;
- enrolled course homepage with module grid/roadmap;
- table of contents;
- launch wrapper and manual launch fallback;
- focused player opening in a separate window/tab or focused player shell;
- fixed top player header;
- thin progress strip;
- left toolbar with visible labels;
- previous/next buttons;
- help overlay with dark background and arrows/labels;
- accessibility modal;
- split-screen module covers;
- welcome video screen;
- learning outcomes screen;
- clickable cards and modal explanations;
- downloadable resource button;
- process diagram screens;
- case description modal;
- knowledge checks;
- feedback modals;
- summary tabs;
- completion screen;
- return-to-platform progress saved state.

## Adapt for HRBA
Adapt all content and identity:

- replace UNICEF/Agora branding with CSO Learning Hub / DEC branding;
- replace child-rights content with HRBA in CSO practice;
- replace UNICEF/EU images with locally grounded CSO practice visuals;
- replace child-specific case logic with HRBA project-cycle, rights-holder, duty-bearer, participation, accountability, MEAL, safety, and enabling-environment logic;
- replace generic quiz feedback with adult-learning feedback;
- replace certificate inconsistencies with one consistent HRBA certificate rule;
- use low-bandwidth alternatives for video and media;
- use safe fictional or composite stories/cases/scenarios.

## Do Not Copy Rigidly
Do not copy these as fixed rules:

- 6 screens for all introductions;
- 26 screens for all modules;
- Egyptian cotton case structure;
- child-protection content sequence;
- UNICEF/EU logos or visual identity;
- exact Agora copy;
- exact module title structure;
- quiz wording that feels punitive or childlike;
- any inconsistency that existed in the source recreation specs.

## No Fixed Screen-Count Rule
Each HRBA module must be screen-planned from the approved module storyboard and audit. The number of screens should be determined by:

- objective count and complexity;
- concept explanation needs;
- practice requirements;
- case/scenario depth;
- media needs;
- tool/worksheet activity;
- accessibility alternatives;
- feedback states;
- summary and completion logic.

## Fidelity Rule
Fidelity applies to architecture, layout discipline, interaction clarity, navigation, and learner flow — not to subject-specific content sequence.
