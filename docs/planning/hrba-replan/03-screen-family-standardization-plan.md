# Screen-Family Standardization Plan

| Screen family | Current best example in course if known | Current problem | Recommended standard pattern | Modules/screens affected | Urgency | Fix class | Acceptance criteria |
| ------------- | --------------------------------------- | --------------- | ---------------------------- | ------------------------ | ------- | --------- | ------------------- |
| Module cover screens | Module 2/3/4 covers appear visually strong in QA evidence | Need consistent image alt, route unlock, CTA, mobile layout, and content-safe text surfaces. | Standard cover with title, duration, concise purpose, accessible image, clear CTA state, and safe text container. | M1-M5, final assessment cover | Can wait until Batch 3 unless evidence blocks commit | design-system decision + QA-only | Cover screens pass desktop/mobile/alt/route checks. |
| Intro video / before-you-begin screens | Module 2 has poster treatment but still placeholder status | Modules 2-5 placeholders weaken readiness. | If video unavailable, use polished static intro with no empty slot, transcript/caption status, and module purpose. | M2-S01A, M3/M4/M5 intro video screens | Urgent before learner testing | content-only or media | No "video will appear" placeholder before learner testing. |
| Learning objective screens | Module 4 objectives have Batch 1 safety wording evidence | Objectives can be dense or not visibly tied to practice/assessment. | Objectives with one practice/portfolio evidence connection and concise module map. | All modules | Medium | content-only/block configuration | Learner can see what they will do and how it is checked. |
| Opening scenario/problem screens | Module 2 rights issue hook and Module 3 project context are strong foundations | Some openings are information-rich without focus cues. | Scenario + "look for" cues + short HRBA lens prompt. | M1 water point, M2 opening, M3/M4/M5 case starts | Medium | content-only | Screenshot shows cue text and no overload. |
| Concept explanation screens | Module 2 compact reveal screens after Batch 1B | Reveal/card patterns can become repetitive and cramped. | Visible core idea, optional details, minimal gated reveal, accessible tab/reveal state. | Modules 1-5 concept screens | Batch 3 | screen-family pattern | Keyboard and screen-reader behavior verified; no forced reveal unless justified. |
| Story/case screens | Module 3 and Module 5 story-based screens | Risk of sensitive examples or too much narrative before task. | Short case, safe/generalized framing, explicit role/risk cue. | M3 design story, M5 ethical story/reporting | Batch 2A/3 | content-only | Case supports task without identifiable details. |
| Practice activity screens | Module 2 applied practice screens | Many complex tasks lack worked examples and clear success criteria. | Worked example -> guided choice -> feedback -> independent action. | M2-S06/S15/S17, Module 3 studio, Module 5 MEAL/reporting | Urgent Batch 2A | instructional design/content | Each target task has example and concise instructions. |
| Worked example screens | Not systematic; some existing examples embedded | Examples are uneven across practice clusters. | Reusable example block: scenario, choice, rationale, safe note, transition to learner task. | Modules 2-5 | Urgent Batch 2A | content-only/block configuration | Examples are short, locally relevant, and safeguard-aware. |
| Knowledge check screens | Module 2 KC is functional in Batch 0 smoke | Accessibility labels, feedback, scoring/completion, and density need verification. | One question focus, explicit labels, clear feedback, non-color-only state, completion summary. | Modules 2-5 and final assessment | Urgent before learner testing | content + technical QA | Keyboard, feedback, refresh, and completion evidence passes. |
| Feedback states | Module 2 repair feedback works but needs accessibility verification | Feedback can be hidden, dense, or not announced. | Feedback adjacent to action, concise, aria-live or equivalent as appropriate, not color-only. | Practice/KC screens | Medium | screen-family pattern | Feedback visible and perceivable after action. |
| Portfolio checkpoint screens | Batch 1 safety wording broadly added | Screens are high-density and high-risk for unsafe input. | Privacy/safety notice above fields, specific small fields, save confirmation, refresh persistence. | M1-M5 portfolios/action plan | Urgent Batch 2B | content + QA | No unsafe input invitation; labels/persistence pass. |
| Self-assessment/forms | Module 2 portfolio smoke showed persistence but label risk | Form labels and helper text need verification across modules. | Explicit label/instruction association, concise placeholder, privacy note, save state. | All text inputs, portfolio, self-assessment | Urgent Batch 2B/5 | technical QA/content | Label audit and refresh persistence evidence. |
| Resource pack screens | Module 5 resource pack flagged in module-by-module list | Useful but may be link-heavy and unverified. | Grouped resources, descriptive links, keyboard focus, updated safeguarding references. | Module resource packs | Later | content-only + QA | Links and focus are accessible. |
| Module summary screens | Some summaries bridge well | Summary-to-next-module bridges may be inconsistent. | Learning recap + portfolio reminder + next module bridge. | M1-M5 summaries | Medium | content-only | Summary prepares learner for next task. |
| Completion/transition screens | Module completion screens exist; Batch 0 did not full-flow all modules | Unlock/progress/certificate interactions need full proof. | Save progress, confirm completion, clear next action, route guard verification. | M1-M5 completion, final bridge | Urgent for learner testing | technical QA/protected if needed | Full end-to-end route/progress evidence. |
