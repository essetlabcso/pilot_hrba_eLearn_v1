# Module 1 Implementation Plan V1

Date: 2026-06-08

## Implementation approach

Implement Module 1 in controlled batches. Do not ask the coding agent to “improve the module” generally. Use deterministic screen batches with acceptance criteria and evidence pack requirements.

## Batch sequence

### Batch 1 — Repo placement and global player/no-scroll foundation
- Add this handover package to the repo.
- Copy SVG assets into the agreed public asset folder.
- Confirm Module 1 route and data structure.
- Apply no-scroll desktop screen standard.
- Verify menu title, top title, progress indicator, and screen count.
- Do not change learner-facing content yet unless needed to connect the spec.

### Batch 2 — Screens M1-S01 to M1-S04
- Cover, learning objectives, value framing, learning journey.
- Use available S02 and S03 icons.
- Implement card reveals and journey stepper.

### Batch 3 — Screens M1-S05 to M1-S07
- Water project story, HRBA lens, simple HRBA explanation.
- Implement hotspot/reveal logic.
- Use placeholder only if missing scene/lens assets are not yet available, but mark clearly in evidence pack.

### Batch 4 — Screens M1-S08 to M1-S14
- Everyday CSO work, invisibility, connected rights, rights-holders, responsibility, participation, lens shift.
- Use S08 and S09 icons.
- Confirm missing S10 connected-rights assets before finalizing M1-S10.

### Batch 5 — Screens M1-S15 to M1-S17
- Knowledge check, self-assessment, action commitment.
- Implement non-obvious feedback and portfolio state saving.

### Batch 6 — Screens M1-S18 to M1-S19
- Synthesis and completion.
- Mark Module 1 complete and return to course page.

### Batch 7 — Full Module 1 QA
- Desktop screenshots for every screen.
- Mobile screenshots for key screens.
- Keyboard navigation check.
- State persistence check.
- Console error check.
- Asset loading check.
- Completion and LMS return check.

## Evidence pack required after every batch

The coding agent must return:
1. list of files changed;
2. summary of implementation;
3. screenshots of modified screens in desktop;
4. mobile screenshots for key affected screens;
5. confirmation of no desktop vertical scrolling;
6. confirmation of interaction completion logic;
7. confirmation of keyboard navigation;
8. confirmation of no console errors;
9. notes on incomplete items;
10. recommended next batch.
