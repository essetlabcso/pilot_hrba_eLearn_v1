# Module 1 Premium Visual and Interactive Design Specification V1

Course: Applying the Human Rights-Based Approach in CSO Practice  
Module: Module 1 — Starting the HRBA Learning Journey  
Version: V1 handover package  
Date: 2026-06-08

## 1. Design intent

Module 1 must feel like a premium, focused, guided e-learning experience for local CSO practitioners. It should not feel like a long scrolling manual, a static PowerPoint export, or a generic LMS page.

The learner experience should be calm, spacious, visual, practical, and action-oriented. Each screen should have one clear learning purpose and one clear learner action.

## 2. Non-negotiable screen rule

On desktop, every learner-facing screen must fit within the visible course-player area without vertical scrolling.

If a screen cannot fit:
1. shorten the text;
2. move detail into a reveal interaction;
3. use staged animation/progressive reveal;
4. split the content into a second screen;
5. move secondary material to glossary/resources.

Do not hide important content below the fold.

## 3. Global visual system

### Colors
- Deep navy: #0F172A
- Primary blue: #3B99D4
- Accent green: #91C852
- Dark ink: #111827
- Secondary text: #6B7280
- Light background: #F9FAFB
- Soft blue background: #F3F7FA
- White surface: #FFFFFF
- Border: #E5E7EB
- Soft border: #EEF2F7
- Warning orange: #F97316
- Critical red: #EF4444

### Typography
- Use a strong clean sans-serif for UI and body text.
- Use large, bold, high-contrast headings.
- Keep paragraphs short.
- Avoid dense text blocks.
- Use 3–6 short cards instead of long bullet lists where possible.

### Layout
- Use a centered slide-like canvas inside the player.
- Prefer 16:9 or 16:10 composition logic.
- Use clear content zones: title zone, visual/interaction zone, action zone, transcript/caption zone only where required.
- Avoid placing learner content behind sticky headers or sidebars.
- Use generous white space.

## 4. Course-player behavior

The player must preserve:
- left learning tools menu;
- top module title, current screen title, screen count, progress indicator;
- Prev / Next / Exit controls;
- Return to LMS button;
- captions/audio controls;
- reload state behavior.

The menu labels must match the final screen titles exactly.

## 5. Interaction standards

Every interaction must have:
- clear instruction before interaction;
- visible completion state;
- accessible keyboard path;
- screen-reader labels;
- mobile tap targets;
- feedback after choice or reveal;
- state persistence after reload where appropriate.

Continue/Next should be enabled only when required interactions are completed, except when a screen is intentionally optional.

## 7. Mobile behavior

Desktop no-scroll is required. On mobile, vertical scrolling may be allowed when unavoidable, but each screen must remain readable, tap-friendly, and logically staged. Cards should stack, interactions should remain keyboard/touch accessible, and no content should be hidden behind fixed navigation.

## 8. Accessibility and safety requirements

- Every meaningful SVG/image must have alt text.
- Decorative visuals must be marked decorative.
- Interactive graphics must have a text alternative.
- All buttons must have clear labels.
- Focus order must follow visual order.
- Color alone must not communicate correctness or status.
- Avoid motion-heavy animations; respect reduced motion.
- Learner inputs must not request real names, active complaints, safeguarding details, legal disputes, confidential records, beneficiary lists, or raw organizational data.

## 9. Developer acceptance criteria

A screen is accepted only if:
1. it matches the approved content spec;
2. it fits desktop without vertical scrolling;
3. it has one clear learning purpose;
4. it uses the specified interaction pattern;
5. it has correct completion logic;
6. state persists after reload where relevant;
7. menu title, top title, and screen count are correct;
8. keyboard navigation works;
9. alt text/labels are included;
10. no console errors appear.
