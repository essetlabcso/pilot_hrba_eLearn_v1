# 07 QA and Acceptance Gates

## Gate 1 — Design Lock Acceptance
The improved design specification is locked only if:

1. The two-layer platform/player architecture is retained.
2. Agora-inspired layout and interaction strengths are preserved.
3. DEC / CSO Learning Hub branding is required.
4. HRBA content and block logic remain source-of-truth.
5. No fixed 26-screen rule remains.
6. Safety and accessibility are binding requirements.
7. Module 1 is identified as the first prototype.

## Gate 2 — Module Audit Readiness
Before module audit begins, the team must have:

- locked design decisions;
- module audit matrix;
- list of module workbooks;
- source document register;
- visual asset system;
- safety and accessibility rules;
- audit scoring method.

## Gate 3 — Module 1 Prototype Acceptance
Module 1 prototype is acceptable only if it demonstrates:

- platform launch flow;
- focused player shell;
- help overlay;
- accessibility support;
- learning objectives;
- HRBA concept teaching;
- interactive examples;
- modal explanations;
- practice check;
- feedback;
- summary;
- completion;
- return-to-platform progress update.

## Gate 4 — Module Build Acceptance
Each module is acceptable only if:

- objectives are practical and action-oriented;
- content is learner-facing and clean;
- screen count fits instructional purpose;
- block types are purposeful;
- cases/stories/scenarios are safe and realistic;
- visuals have instructional purpose;
- assessments align with objectives;
- completion logic works;
- accessibility requirements are met;
- safety risks are controlled.

## Gate 5 — Full Course Publish Acceptance
The full course is acceptable only if:

- all modules pass QA;
- final test and certificate rule are verified;
- progress and completion logic work;
- resources and downloads work;
- keyboard/caption/transcript/alt text support is verified;
- no sensitive learner data is required;
- public platform pages do not expose internal/admin states;
- course can be monitored and improved after pilot.
