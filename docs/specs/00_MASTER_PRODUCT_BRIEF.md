# 00 Master Product Brief

## Product
CSO Learning Hub — Applying the Human Rights-Based Approach (HRBA) in CSO Practice.

## Core Purpose
Create a premium, Agora-inspired, two-layer e-learning course experience for local and grassroots CSO learners. The course must preserve the strong platform/player logic observed in the UNICEF Agora example while adapting all branding, content, examples, cases, visuals, tools, and assessment to the CSO Learning Hub HRBA course.

## Strategic Learning Purpose
The HRBA course should help CSO staff and leaders apply HRBA in project design, implementation, MEAL, participation, accountability, safeguarding, evidence use, and adaptive learning. The course should not only define HRBA; it should help learners practice asking better CSO questions:

- Who has rights?
- Who has responsibilities?
- Who is excluded?
- What barriers exist?
- Who participates?
- Who is accountable?
- What information is safe to collect?
- What should the CSO change?
- How will we learn and adapt?

## Architecture
The course is implemented as a two-layer learning system.

### Layer 1 — Course Platform / LMS Layer
Responsible for:

- public course catalogue;
- course overview page;
- enrolled course homepage / roadmap;
- module outline and table of contents;
- module launch pages;
- progress indicators;
- completion checkmarks;
- next/previous module navigation;
- final assessment and certificate pathway;
- support, accessibility, and resource links.

### Layer 2 — Focused Course-Player Layer
Responsible for:

- module cover;
- one screen or focused block sequence at a time;
- fixed player header;
- left toolbar;
- progress display;
- next/previous navigation;
- help overlay;
- accessibility modal;
- glossary/resources/captions/transcripts;
- video and transcript screens;
- clickable cards;
- modal explanations;
- scenario and case interactions;
- practice checks;
- feedback modals;
- summary tabs;
- completion screen;
- return-to-platform flow.

## Design Inspiration
The UNICEF Agora example provides the structural benchmark for platform/player separation, visual discipline, slide-like focused screens, interactive overlays, and progress return. It must not be treated as a rigid content pattern or fixed screen count.

## Non-Negotiable Correction
The 26-screen Agora Module 1 example is not a fixed HRBA module rule. Each HRBA module uses the number of screens and sub-screens required by its own learning purpose.

## Phase 1 Scope
Phase 1 locks the design specification and prepares for module audit and Module 1 prototype. It does not yet rewrite all modules or build the full course.
