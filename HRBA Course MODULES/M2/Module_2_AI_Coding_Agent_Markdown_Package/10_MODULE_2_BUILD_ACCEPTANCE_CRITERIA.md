# Module 2 Build Acceptance Criteria

## Content structure

| Check | Pass condition |
|---|---|
| Clean content only | Learner-facing build excludes QA history, source inventories, evidence packs, change logs, approval locks, and internal reviewer notes. |
| Approved title | Module title is “Human Rights in Everyday CSO Work.” |
| Approved sequence | Seven sections appear in approved order. |
| Correct screen count | 36 learner-facing screens/blocks are represented. |
| Module 1 bridge | Opening connects the rights-holder shift from Module 1 to rights recognition in Module 2. |
| Practical tone | Human rights are presented as practical CSO standards, not distant legal language. |
| Non-legalistic standards | Standards are framed as practical guides, not legal advice. |

## Assessment and feedback

| Check | Pass condition |
|---|---|
| No early substantive quiz | Section 1 has no human-rights knowledge quiz. |
| Checks after teaching | Matching, characteristics check, sorting, standards check, scenario decision, and final quiz appear after related content. |
| Final quiz limit | Final Module 2 quiz has five MCQs or fewer. |
| Option-level feedback | Every answer option has feedback. |
| Feedback wording | Weaker responses use “Not quite,” not “Incorrect.” |
| Encouraging correct feedback | Best responses use “That’s right” or “Good choice.” |
| Formative-only rule | No Module 2 check affects certificate eligibility. |
| Certificate rule | Learner copy states certificate is linked to final course test score of 80% or above. |

## Portfolio and worksheets

| Check | Pass condition |
|---|---|
| Portfolio output | “My Everyday Rights Lens” checkpoint appears in Section 7. |
| Portfolio privacy | Portfolio inputs and optional notes are private by default. |
| Optional notes safe | Optional note fields include safety helper text. |
| Deterministic synthesis | Portfolio summary can be generated from structured choices without raw notes. |
| Worksheets included | Everyday Rights Mapping and Rights Relevance worksheets appear as tool activities. |
| Worksheet access | Both worksheets have downloadable and in-platform options. |
| No uploads | Learners are not required to upload files. |
| Certificate separation | Portfolio and worksheet outputs do not affect certificate eligibility. |

## Safety and data

| Check | Pass condition |
|---|---|
| No sensitive data requests | No screen asks for names, real cases, active complaints, safeguarding details, confidential records, political details, beneficiary lists, raw data, or uploads. |
| Fictional scenarios | Ayele/Lomi examples are clearly fictional or demonstration examples. |
| Standards disclaimer | Section 6 states: “This course supports learning and practical reflection. It does not provide legal advice.” |
| Data minimization | Only necessary structured learning data is saved. |
| No raw reflections to AI | Raw notes, worksheet entries, and portfolio content are not sent to AI services. |
| No public ranking | No activity ranks participants or CSOs. |

## Accessibility and low bandwidth

| Check | Pass condition |
|---|---|
| Keyboard access | All interactions are keyboard accessible. |
| Tap-friendly | All interactions work on mobile. |
| Non-drag alternative | Matching and sorting have tap/dropdown/button alternatives. |
| Screen-reader support | Forms, controls, buttons, feedback, cards, tabs, and checklists have readable labels. |
| Text alternatives | Hotspot, timeline, process, diagrams, icons, and visuals have text alternatives. |
| No color-only meaning | Scores, result bands, feedback, and status use text labels. |
| Mobile layout | Cards, tabs, timelines, forms, and process blocks stack cleanly. |
| Low bandwidth | Required learning does not depend on video, heavy media, PDFs, or external embeds. |

## Asset control

| Check | Pass condition |
|---|---|
| No invented filenames | Source-named assets are preserved; missing assets remain placeholders. |
| Alt text included | Every asset placeholder includes alt text. |
| Local grounding | Visual direction supports Ethiopian/East African local CSO practice. |
| Brand consistency | DEC/CSO Learning Hub color system is applied where relevant. |

## Final implementation acceptance

Module 2 is accepted when:

1. all approved screens are implemented in order;
2. required interactions work;
3. feedback appears exactly as specified;
4. all portfolio and worksheet outputs remain private by default;
5. no sensitive data is requested;
6. certificate logic is not triggered by Module 2;
7. standards are not presented as legal advice;
8. all accessibility and low-bandwidth requirements are met;
9. asset placeholders are not replaced with invented filenames;
10. learner-facing screens do not show internal metadata.
