# Module 2 Safety, Accessibility, and Data Rules

## Safety principle

Module 2 must be safe by default. It should help learners apply a rights lens without exposing people, communities, organizations, complaints, safeguarding issues, or sensitive civic-space information.

## Do not request

Never ask learners to submit:

- real names of people, staff, officials, organizations, or communities;
- real case details;
- active complaint details;
- safeguarding or protection information;
- beneficiary lists;
- personal data;
- legal disputes;
- internal reports;
- confidential documents;
- political or civic-space-sensitive details;
- raw organizational data;
- uploads.

## Safe alternatives

Use:

- fictional examples;
- broad role and group categories;
- broad work areas;
- non-identifying descriptions;
- structured choices;
- optional private notes with safety helper text;
- portfolio summaries rather than raw evidence.

## Standard-use safety rule

Always frame standards as practical learning and analysis tools. Include this message in Section 6:

> This course supports learning and practical reflection. It does not provide legal advice.

Do not encourage learners to make legal claims about real cases or publicly accuse people/institutions.

## Privacy rules

| Data type | Default visibility |
|---|---|
| Safety reminder viewed | System status only |
| Matching/sorting/check completion | Learner/system only |
| Optional portfolio notes | Learner private portfolio only |
| Worksheet entries | Learner private portfolio only if saved |
| Everyday Rights Lens checkpoint | Learner private portfolio only |
| Module quiz completion | Learner/system only |
| Module quiz score | Formative only; no certificate effect |

## Certificate rule

- Module 2 checks are formative only.
- Module 2 does not issue certificates.
- Certificate eligibility remains tied to the final course test score of 80% or above.

## AI/data restriction

Raw reflections, optional notes, worksheet entries, and portfolio checkpoint content should not be sent to AI services. If AI is later used for safe summaries, use structured non-sensitive tags or participant-approved safe summaries only.

## Accessibility requirements

| Requirement | Rule |
|---|---|
| Keyboard access | Required for all interactive blocks |
| Tap-first mobile | Required for all interactions |
| Screen-reader labels | Required for buttons, radio buttons, checkboxes, tabs, cards, inputs, and forms |
| Non-drag alternative | Required for matching and sorting |
| Text alternative | Required for hotspot, timeline, process, images, icons, diagrams |
| Mobile stack | Required for cards, columns, comparisons, and forms |
| No color-only meaning | Required for scores, feedback, status, and selected states |
| Plain language | Required throughout |
| Optional text fields | Must include safety helper text |
| Low-bandwidth fallback | Required for all media and visuals |
| Visible focus states | Required for all controls |
| Large tap targets | Required for mobile |

## Low-bandwidth rules

The module must be usable without:

- streaming video;
- high-resolution images;
- drag-heavy interactions;
- PDF download dependency;
- external embeds.

Where assets are heavy, provide:

- lightweight SVG;
- compressed image;
- text alternative;
- in-platform worksheet fields;
- printable/downloadable option only as supplement.

## Safe helper text

Use before any optional text field:

> Keep this safe and general. Do not include names, real cases, active complaints, safeguarding details, legal disputes, political details, confidential documents, beneficiary lists, or raw organizational data.
