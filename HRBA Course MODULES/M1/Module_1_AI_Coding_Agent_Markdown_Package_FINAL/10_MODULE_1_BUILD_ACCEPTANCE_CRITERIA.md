# Module 1 Build Acceptance Criteria

## Content structure

| Check | Pass condition |
|---|---|
| Clean content only | Learner-facing build excludes QA history, evidence packs, change logs, source inventories, and internal reviewer notes. |
| Approved title | Module title is “Starting Your HRBA Learning Journey — From Good Intentions to Rights-Based Practice.” |
| Approved section flow | Module uses the seven approved sections in order. |
| HRBA starts early | Section 2 begins practical HRBA relevance after short orientation. |
| No excessive orientation | Opening content is concise and does not delay HRBA learning. |

## Assessment and feedback

| Check | Pass condition |
|---|---|
| No early HRBA knowledge check | Section 1 check covers only safety, privacy, course mechanics, and certificate logic. |
| Substantive checks follow learning | Scenario, sorting, matching, self-assessment, and quiz appear only after related content. |
| Quiz limit | Module 1 quiz contains exactly five MCQs or fewer. |
| Option-level feedback | Every response option has feedback. |
| Feedback wording | Weaker responses use “Not quite,” not “Incorrect.” |
| Encouraging correct feedback | Best responses use “That’s right” or “Good choice.” |
| Formative-only rule | No Module 1 check affects certificate eligibility. |
| Certificate rule | Learner copy states certificate is linked to final course test score of 80% or above. |

## Self-assessment

| Check | Pass condition |
|---|---|
| 16-item survey | Self-assessment includes all 16 items. |
| Eight domains | Items map to eight HRBA domains, two items per domain. |
| Response scale | Scale includes 0, 1, 2, 3, and Not sure / need to check. |
| Score bands | Results use 0–15, 16–27, 28–39, 40–48 bands. |
| Confidence flag | More than four Not sure responses triggers low-confidence message. |
| Priority selection | Learner chooses exactly two priority domains. |
| Privacy | Result is private, non-ranking, and not certificate-linked. |

## Portfolio

| Check | Pass condition |
|---|---|
| Portfolio value explained | Module introduces private HRBA Learning Portfolio. |
| Ayele demo included | Demo clearly states Ayele and Lomi Community Development Association are fictional examples. |
| Optional notes safe | Optional note fields include safety helper text. |
| Private by default | Portfolio inputs are not visible to peers, donors, or organization users by default. |
| Deterministic synthesis | Portfolio summaries can be generated from structured choices without exposing raw notes. |
| Certificate separation | Portfolio does not affect certificate eligibility. |

## Safety and data

| Check | Pass condition |
|---|---|
| No sensitive data requests | No screen asks for names, real cases, complaints, safeguarding details, confidential records, political details, or uploads. |
| Safe Learning Agreement | Learner must accept before continuing. |
| Fictional scenarios | Lomi and Ayele examples are clearly marked as demonstration examples. |
| Data minimization | Only necessary structured learning data is saved. |
| No raw reflections to AI | Raw notes and private portfolio content are not sent to AI services. |

## Accessibility and low bandwidth

| Check | Pass condition |
|---|---|
| Transcript | Welcome video has transcript fallback. |
| Captions | Any video/audio has captions or transcript. |
| No video-only requirement | Learner can complete course through text pathway. |
| Keyboard access | All required interactions are keyboard accessible. |
| Tap-friendly | All interactions work on mobile. |
| Non-drag alternative | Sorting and matching have tap/dropdown or button alternatives. |
| Screen-reader support | Forms, controls, buttons, feedback, and cards have readable labels. |
| Text alternatives | Roadmap, diagrams, maps, icons, and visuals have text alternatives. |
| No color-only meaning | Scores, result bands, feedback, and status use text labels. |
| Mobile layout | Cards, columns, comparisons, and survey screens stack cleanly. |

## Asset control

| Check | Pass condition |
|---|---|
| No invented filenames | Assets use placeholders unless approved filenames are provided. |
| Alt text included | Every asset placeholder includes alt text. |
| Local grounding | Visual direction supports Ethiopian/East African local CSO practice. |
| Brand consistency | DEC/CSO Learning Hub color system is applied where relevant. |

## Final implementation acceptance

Module 1 is accepted when:

1. all approved screens are implemented in order;
2. required interactions work;
3. feedback appears exactly as specified;
4. self-assessment scoring works correctly;
5. all portfolio and self-assessment outputs remain private by default;
6. no sensitive data is requested;
7. certificate logic is not triggered by Module 1;
8. all accessibility and low-bandwidth requirements are met;
9. asset placeholders are not replaced with invented filenames;
10. learner-facing screens do not show internal metadata.
